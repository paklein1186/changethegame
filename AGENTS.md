## Edge functions

- Keep `nodeModulesDir: "none"` in root `deno.json`: published functions resolve
  `npm:` imports from Deno's cache, not gitignored local dependency folders.
- Run `deno install` inside `supabase/functions` after a clean checkout or whenever
  `deno check` reports a missing package: the preview build type-checks every
  `supabase/functions/*/index.ts`, and the npm packages those functions import are
  declared in `supabase/functions/package.json` and installed into the gitignored
  `supabase/functions/node_modules`.
- The root `deno.json` import map is not cosmetic: it points the generated MCP
  function's `npm:@supabase/supabase-js@^2.95.3` at the `2.57.2` the hand-written
  functions pin, so one install satisfies both. Removing it makes the MCP function
  fail type checking again.
- `supabase/functions/mcp/index.ts` is generated by the `mcpPlugin()` in
  `vite.config.ts` from `src/lib/mcp/`. Author in `src/lib/mcp/`, never by hand.
  Because esbuild erases type annotations when bundling, tool handlers must build
  their result object inline (the literal `type: "text"` only survives where the
  return is contextually typed) and shared helpers must not rely on parameter
  annotations alone.
